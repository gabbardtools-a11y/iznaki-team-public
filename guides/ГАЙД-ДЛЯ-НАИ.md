## ⚙️ Архитектура i18n

### Файлы (всё в `/var/www/iznaki/`)

| Файл | Назначение |
|---|---|
| `src/lib/i18n/translations.ts` | **Словарь всех переводов** (180+ ключей × 3 языка) |
| `src/lib/i18n/useLanguage.ts` | Клиентский React-hook |
| `src/lib/i18n/server.ts` | Серверное чтение cookie (для SSR) |
| `src/middleware.ts` | Обработка `/en/` и `/zh/` URL |
| `src/app/layout.tsx` | Читает cookie, передаёт `lang` в Header |

### Как это работает

1. **Пользователь заходит на `/en/vip/olga`**
2. `middleware.ts` перехватывает URL, убирает `/en`, устанавливает cookie `lang=en`
3. `layout.tsx` (server component) читает cookie через `getLang()`
4. Передаёт `lang` как prop в `Header`, `HeroSection`, `CatalogSection`
5. Server components (например, `vip/olga/page.tsx`) вызывают `t(key, lang)` — получают нужный перевод
6. Client components (Header, HeroSection) используют `useLanguage(initialLang)` hook

## 📝 Как переводить разные типы контента

### Тип 1. Статичные тексты (кнопки, заголовки, лейблы)

**Где:** `src/lib/i18n/translations.ts`

**Добавить новый ключ** (ОБЯЗАТЕЛЬНО все 3 языка):

```typescript
'catalog.newButton': {
  ru: 'Новая кнопка',
  en: 'New button',
  zh: '新按钮',
},
```

**Использовать в client component:**
```tsx
'use client';
import { useLanguage } from '@/lib/i18n/useLanguage';

export function MyComponent({ lang = 'ru' }: { lang?: Lang }) {
  const { t } = useLanguage(lang);
  return <button>{t('catalog.newButton')}</button>;
}
```

**Использовать в server component:**
```tsx
import { getLang } from '@/lib/i18n/server';
import { t } from '@/lib/i18n/translations';

export default async function MyPage() {
  const lang = await getLang();
  const tt = (key: Parameters<typeof t>[0]) => t(key, lang);
  return <h1>{tt('catalog.newButton')}</h1>;
}
```

### Тип 2. Уникальные тексты (без ключа в словаре)

Иногда текст встречается 1 раз — нет смысла добавлять ключ. Используй helper `L()`:

```tsx
// В server component
const L = (zh: string, en: string, ru: string) =>
  lang === 'zh' ? zh : lang === 'en' ? en : ru;

<p>{L('已验证', 'Verified', 'Проверен')}</p>
```

### Тип 3. Длинные тексты (параграфы, описания)

Для длинных текстов используй `lang === 'zh' ? ... : lang === 'en' ? ... : ...`:

```tsx
<p>
  {lang === 'zh'
    ? '这段中文文字...'
    : lang === 'en'
      ? 'This English text...'
      : 'Этот русский текст...'}
</p>
```

Или через `L()` с многострочными аргументами:

```tsx
{L(
  `非常长的中文文本...`,
  `Very long English text...`,
  `Очень длинный русский текст...`
)}
```

### Тип 4. SEO metadata

Каждая страница с динамическим контентом — `generateMetadata()`:

```typescript
export async function generateMetadata(): Promise<Metadata> {
  const lang = await getLang();
  const isZh = lang === 'zh';
  const isEn = lang === 'en';
  return {
    title: isZh ? '...' : isEn ? '...' : '...',
    description: isZh ? '...' : isEn ? '...' : '...',
    openGraph: {
      locale: isZh ? 'zh_CN' : isEn ? 'en_US' : 'ru_RU',
    },
  };
}
```

### Тип 5. Данные знаков (контакты, цены, классы)

**Это важно!** Поля `seller`, `sellerEmail`, `sellerPhone`, `price`, `classes` в `data.ts` — **ОБЩИЕ для всех языков**. Не дублируй!

```typescript
// ✅ ПРАВИЛЬНО — контакты в data.ts, отображаются на всех языках
seller: "Igor Broker",
sellerEmail: "${SELLER_EMAIL_EXAMPLE}",
sellerPhone: "+7(968)9973835",
```

Если меняешь контакты в `data.ts` → они обновятся сразу в RU, EN и ZH.

## ⚖️ ЗАКОН №3 — краткая версия

### 📜 Главное правило

**Любое изменение в русской версии сайта должно автоматически отражаться в английской и китайской версиях.**

### 5 правил

1. **Любой текст — в 3 языках** (ru/en/zh одновременно в `translations.ts`)
2. **Хардкод запрещён** — использовать `t()` или `L()`
3. **Данные знаков — общий источник** (`data.ts`)
4. **Описания знаков — переводить отдельно** (поле `descriptionEn`/`descriptionZh` в `data.ts`)
5. **SEO metadata — через `generateMetadata()`** с 3 языками

### 🚫 Запрещено

```typescript
// ❌ Только 2 языка
'key': { ru: 'Текст', en: 'Text' }  // нет zh

// ❌ Хардкод в JSX
<button>Click me</button>

// ❌ Изменил RU, забыл EN/ZH
'key': {
  ru: 'Новый текст 2024',
  en: 'Old text',  // не обновил
  zh: '旧文本',     // не обновил
}

// ❌ Дублировать контакты в переводах
'seller.email': { ru: '...', en: '...', zh: '...' }
```

### ✅ Чек-лист перед деплоем

- [ ] Новый ключ в `translations.ts` имеет ru/en/zh
- [ ] Нет хардкод-текстов в JSX
- [ ] `generateMetadata()` работает для всех языков
- [ ] Контакты в `data.ts` обновились во всех языках автоматически
- [ ] Проверены `/en/...` и `/zh/...` версии
- [ ] `<html lang>` корректный (`ru`/`en`/`zh`)

6. **Сохрани переводы в git** — после каждого изменения делай commit:
   ```bash
   cd /var/www/iznaki && git add -A && git commit -m "i18n: ..."
   ```
